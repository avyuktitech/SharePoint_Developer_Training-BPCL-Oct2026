# Azure SQL Explorer (SPFx + Azure Functions + Azure SQL)

A SharePoint web part that shows data from Azure SQL Database: tables with paging, plus files and images stored in the database. Images display directly, text and JSON files open in place, and CSV files appear as tables.

It starts with built-in sample data, so you can see it working before setting up Azure.

## How it works

```text
SharePoint page  ->  Azure Functions API  ->  Azure SQL Database
                 Entra ID token         managed identity
                 for the user           (no stored password)
```

**A web part can't connect to SQL directly.** Browsers can't open SQL connections, and a connection string in the page would expose it to every visitor. The API sits in between:

- **App Service Authentication** rejects any call without a valid Entra ID token from your tenant.
- **The API can only read what it lists.** Table and column names come from a fixed list in `api/src/catalog.js`, and values are passed as parameters, so a request can't change the SQL.
- **The database login is read-only.** The Function App's managed identity only has `db_datareader`.

| Path | Purpose |
| --- | --- |
| `src/webparts/azureSqlExplorer/AzureSqlExplorer.tsx` | The tables and files UI |
| `src/webparts/azureSqlExplorer/SqlApiSource.ts` | Calls the API using `AadHttpClient` |
| `src/webparts/azureSqlExplorer/demoData.ts` | The built-in sample data |
| `api/src/catalog.js` | The API's logic and its list of allowed tables |
| `api/src/db.js` | The SQL connection |
| `database/seed.sql` | Creates the sample tables and files (generated by `build-seed.js`) |
| `database/grant-api-access.sql` | Gives the API read-only access |
| `deploy/setup-azure.ps1` | Creates and connects the Azure resources |

## Try it with sample data

Requires Node.js 22.14.x or later 22.x.

```powershell
npm install
npm start
```

Open `https://<tenant>.sharepoint.com/sites/<site>/_layouts/15/workbench.aspx` and add the **Azure SQL Explorer** web part. No Azure setup is needed for this.

## Connect your database

You need an Azure subscription, the [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli) signed in with `az login`, [Azure Functions Core Tools v4](https://learn.microsoft.com/azure/azure-functions/functions-run-local), permission to create app registrations, and the SharePoint Administrator role.

**1. Create the Azure resources.** The script prints the two web part settings at the end, so keep its output.

```powershell
./deploy/setup-azure.ps1 -ResourceGroup rg-spfx-sql -SqlServer <unique-server-name> -FunctionApp <unique-app-name> -FunctionStorage <unique-lowercase-name> -SharePointOrigin https://<tenant>.sharepoint.com
```

**2. Load the data.** In the Azure portal, open the database, go to **Query editor**, and sign in with Entra ID.

1. Run `database/seed.sql`.
2. Run `database/grant-api-access.sql`, replacing `<function-app-name>` with your Function App's name.

**3. Publish the API.**

```powershell
cd api
npm install
func azure functionapp publish <function-app-name>
```

**4. Deploy the web part.**

1. From the project folder, `npm run build` creates `sharepoint/solution/azuresql.sppkg`.
2. Upload it to the tenant App Catalog and enable it.
3. Go to **SharePoint admin center > Advanced > API access** and approve the **SPFx Azure SQL Sample API** `user_impersonation` request.

**5. Add it to a page.** Edit the web part and enter the API address and client ID from step 1.

## Run the API locally

```powershell
cd api
copy local.settings.sample.json local.settings.json   # then fill in your server and database
npm install
npm start
npm test                                              # unit tests, no database needed
```

Locally the API signs in to SQL with your `az login`. Add your IP address under the SQL server's **Networking** settings first. `ALLOW_UNAUTHENTICATED_LOCAL_DEV` turns off the API's sign-in check, so don't set it in Azure.

## Troubleshooting

| What you see | What to check |
| --- | --- |
| "Could not reach the API" | The API access request may not be approved, or the Function App's CORS list may not match your exact SharePoint address. The browser console shows which one. |
| "The API refused access (401)" | Check the issuer and allowed audiences under the Function App's **Authentication** settings. Audiences need both `api://<client-id>` and `<client-id>`. |
| "The API could not read the database (500)" | Check that `grant-api-access.sql` ran and that the `SQL_SERVER` and `SQL_DATABASE` app settings are right. The Function App's logs have the exact error. |
| The first load is slow | The serverless database auto-pauses when idle and can take about a minute to wake up. |

## Limitations

This is a training sample:

- **It's read-only.** It has no way to add or edit rows or files.
- **Everyone signed in sees the same data.** The API checks that a user belongs to your tenant, not who they are. To limit access, require user assignment on the API's enterprise application, or add per-user checks to the API.
- **To show another table,** add it to the `TABLES` list in `api/src/catalog.js`.
- **Files are capped by memory.** The API reads a whole file before returning it, which suits small files like these. Use Blob Storage for large files in production, as in `azure-blob-spfx`.
